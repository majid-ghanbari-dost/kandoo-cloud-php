# بسته ثبت الگوهای پیامک — پیش‌نویس P-33

این سند متن پیشنهادی ثبت الگو است، نه تأیید ارائه‌دهنده و نه مجوز فعال‌سازی. SMS واقعی خاموش بماند تا مالک دامنه، شناسه خط، API key و شناسهٔ الگوها را خارج از مخزن تنظیم کند. یک base URL HTTPS نهایی باید قبلاً توسط مالک تأیید شود؛ جای‌نگهدار زیر هیچ دامنهٔ عملیاتی نیست.

## الگوی اعلان ثابت — بدون متغیر

```text
فاکتور دیجیتال کندو برای شما ثبت شد. برای مشاهده فاکتورها به نشانی https://FINAL-DOMAIN-PLACEHOLDER/account/login مراجعه کنید.
```

آدرس باید پیش از ثبت الگو با URL نهایی و ثابت جایگزین شود؛ هیچ شناسهٔ فاکتور، شماره تلفن یا لینک مخصوص هر فاکتور در الگو یا متغیر قرار نگیرد. تأیید محدودیت متن/نشانی با ارائه‌دهنده لازم است.

## الگوی OTP — یک متغیر

```text
کد ورود به فاکتور دیجیتال کندو: {code}
```

فقط نام متغیر `code` است. کد و کلید API هرگز در مستندات، مخزن یا گزارش لاگ نشوند. فراخوانی فعلی در `src/Sms/FarazAdapter.php` endpoint HTTPS ثابت و هدر `Api-Key` را به‌کار می‌گیرد؛ دریافت پاسخ پذیرش ارائه‌دهنده به معنی تحویل نیست. شناسهٔ خطوط، الگوها و کلید از تنظیم خصوصی خوانده می‌شوند. در CI از ارسال واقعی جلوگیری می‌شود.

## بازبینی کمینه‌سازی داده — پیشنهاد، نه تصمیم حذف

`cloud_sms_announcements` اثبات اعلان تأییدشده و بودجه OTP؛ `cloud_sms_delivery_requests` مانع تکرار ارسال/ابهام؛ challenge و metadata idempotency برای replay و امنیت هستند. طبق حکم P-15 نباید اعلان تأییدشده، ردیف درخواست، fingerprint یا audit فعال را حذف کرد. پیشنهاد پیش از انتشار: مالک/حقوقی مدت نگهداری، تفکیک دادهٔ قابل حذف، دسترسی admin، نسخهٔ پشتیبان و نحوهٔ پاسخ به درخواست حذف را بررسی کند؛ کاهش داده فقط پس از تصویب و بدون نقض قرارداد و idempotency. لاگ دموی حاوی کد/شماره صرفاً محلی است و برای پشتیبانی خارجی ارسال نمی‌شود.

ثبت برآورد اختیاری هر رزرو SMS و نمایش آن در مدیریت فراهم است؛ قیمت و هزینهٔ واقعی ارسال حدس زده نمی‌شود. آزمون تحویل واقعی و ثبت الگو با ارائه‌دهنده **NOT-VERIFIED** است.

### برآورد هزینهٔ رزرو ارسال (محلی، اختیاری)

پیکربندی `sms_cost` به‌صورت پیش‌فرض خاموش است. با فعال‌سازی صریح، هر دو مقدار صحیح غیرمنفی `notification_rials` و `otp_rials` لازم‌اند (۰ تا ۹۹۹۹۹۹ ریال). ردیف برآورد به‌صورت تراکنشی هنگام رزرو هر تلاش اعلان یا OTP و بدون شماره یا متن SMS ثبت می‌شود؛ تکرار کلید، ردیف یا ارسال دوم تولید نمی‌کند. این **برآورد رزرو است نه هزینه واقعی، قبض، تحویل یا پذیرش ارائه‌دهنده**؛ تلاش نامطمئن یا توقف پس از رزرو هم ممکن است حساب شود و طول پیام/تعرفه واقعی با آن تفاوت داشته باشد. مالک باید برآورد را با صورت‌حساب تطبیق دهد؛ قیمت را حدس نزنید. CI از dry adapter و اطلاعات ساختگی استفاده می‌کند و هیچ SMS واقعی ارسال نمی‌کند.

## پک الحاق عملیاتی — چه چیزی در پنل و چه چیزی در `config.php`

**وضعیت: هیچ‌چیز خریداری نشده است.** نه خط رزرو شده، نه الگو ثبت/تأیید شده، نه اعتبار خریداری شده و نه پیامک واقعی ارسال شده است.
این بخش فقط متن‌های آمادهٔ الحاق و نگاشت فیلدها است تا مالک، وقتی تصمیم گرفت، در چند دقیقه ثبت کند.

### الف) آنچه در پنل ارائه‌دهنده وارد می‌شود (متن آماده برای کپی)

| # | فیلد پنل (معمول) | مقدار آماده برای کپی | نکته |
|---|---|---|---|
| ۱ | نام الگو (اعلان) | `kandoo-invoice-notice` | نام فقط برچسب داخلی ارائه‌دهنده است |
| ۲ | متن الگو (اعلان) | `فاکتور دیجیتال کندو برای شما ثبت شد. برای مشاهده فاکتورها به نشانی https://FINAL-DOMAIN-PLACEHOLDER/account/login مراجعه کنید.` | `FINAL-DOMAIN-PLACEHOLDER` را قبل از ثبت با دامنهٔ نهاییِ تأییدشدهٔ مالک جایگزین کنید؛ هیچ متغیری در این الگو نیست |
| ۳ | متغیرهای الگو (اعلان) | هیچ | اگر پنل متغیر اجباری خواست، ثبت نکنید و به PHP-B خبر دهید |
| ۴ | نام الگو (OTP) | `kandoo-customer-otp` | — |
| ۵ | متن الگو (OTP) | `کد ورود به فاکتور دیجیتال کندو: {code}` | نام متغیر باید دقیقاً `code` باشد (حساس به حروف) |
| ۶ | متغیرهای الگو (OTP) | `code` — نوع: عدد/متن کوتاه | طول کد در `customer_auth.code_length` (پیش‌فرض ۶) تعیین می‌شود |
| ۷ | شمارهٔ خط فرستنده | از پنل | همان مقدار در `faraz_sms.line_number` |
| ۸ | کلید API | از پنل، فقط در `config.php` | هرگز در مخزن، سند، گزارش یا چت |

### ب) آنچه در `config.php` (خارج از web root) تنظیم می‌شود

```php
'faraz_sms' => [
    'enabled' => false,                 // تا تأیید الگوها و تست، false بماند
    'dry_run' => false,
    'api_key' => '<از پنل — فقط همین‌جا>',
    'line_number' => '<شمارهٔ خط از پنل>',
    'announcement_pattern' => 'kandoo-invoice-notice',   // شناسهٔ الگو، نه متن آن
    'otp_pattern' => 'kandoo-customer-otp',
],
```

شناسهٔ الگو (نه متن) در پیکربندی می‌نشیند؛ متن در پنل ارائه‌دهنده نگه داشته می‌شود.

### ج) پیکربندی که کد واقعاً می‌فرستد (برای مقایسه با صفحهٔ «آزمایش الگو» در پنل)

درخواست OTP پس از فعال‌سازی (مقادیر ساختگی، `src/Sms/FarazAdapter.php`):

```json
{"code":"kandoo-customer-otp","attributes":{"code":"123456"},"recipient":"09120000001","line_number":"<خط>","number_format":"english"}
```

و درخواست اعلان فاکتور: همان بدنه با `"code":"kandoo-invoice-notice"` و `"attributes":{}` — **بدون** شمارهٔ فاکتور، مبلغ، نام مشتری یا لینک اختصاصی.
پاسخ پذیرش در HTTP 201 بدنهٔ `{"status":"success","data":{"id":...}}` است؛ این پذیرش ارائه‌دهنده است، نه اثبات تحویل، و هیچ تحویل واقعی تا امروز سنجیده نشده است (**NOT-VERIFIED**).

### د) چک‌لیست پیش از روشن‌کردن `enabled`

- [ ] دامنهٔ نهایی تأیید و `FINAL-DOMAIN-PLACEHOLDER` در متن الگو جایگزین شده است.
- [ ] هر دو الگو در پنل **تأیید** شده‌اند و شناسهٔ آن‌ها با `config.php` یکی است.
- [ ] `line_number` از پنل گرفته شده و برای همان حساب است.
- [ ] `php bin/preflight.php --strict` روی هاست سبز است (کلید API کلاینت‌محور نیست، اما config و DB بررسی می‌شوند).
- [ ] یک آزمون با شمارهٔ خودِ مالک انجام و تحویل چشمی تأیید شده است (این تنها راه اثبات تحویل است).
- [ ] `sms_cost` در صورت نیاز به برآورد، با اعداد صورت‌حساب واقعی پر شده است؛ قیمت حدس زده نشده است.

هیچ‌کدام از این بندها در محیط توسعه یا CI قابل اثبات نیست؛ تا انجام نشوند، وضعیت P-33 «متن آماده، ثبت نشده، خرید نشده» است.
