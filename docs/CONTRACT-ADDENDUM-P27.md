# P-27 — executive-approved DeviceBearer transition

Executive ruling: the common wire reference is Hub `docs/openapi.yaml` DeviceBearer, `Authorization: Bearer <device-secret>`. Cloud authenticates the device by its existing SHA-256 digest, scoped to the route store; it preserves the existing `X-Kandoo-Device-Id` + `X-Kandoo-Device-Secret` pair for transition. No database schema or migration changes. Unknown, invalid, absent, ambiguous or wrong-store credentials use the same 401 envelope. When Authorization is supplied it takes precedence and an invalid header cannot fall back to legacy. Hashes are stored, not raw secrets; comparisons use `hash_equals`. A duplicate digest in the same store fails closed. Successful auth still marks the matched device authenticated. Writer fencing remains unchanged. This addendum does not rewrite the frozen CLOUD-CONTRACT.md or its pinned addenda.

The authoritative OpenAPI belongs to the separate C# Hub repository, not this PHP checkout. The requested one-line deprecation there remains a cross-repository handoff item: mark the legacy two-header PHP form deprecated in that file without changing DeviceBearer. This document is not an OpenAPI substitute. C-80b CI alone is not evidence of Hub/PHP interoperability; real replay is P-23.
