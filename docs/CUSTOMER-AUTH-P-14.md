# P-14 customer authentication controls

Customer authentication remains disabled unless explicitly enabled. The existing session cookie is the remembered-device login credential: it is random, hashed server-side, Secure, HttpOnly, SameSite=Strict, has configurable `session_ttl_seconds`, and can be revoked by the CSRF-protected logout action. Expired or revoked sessions cannot access invoices.

The login CSRF/device cookie is random, Secure, HttpOnly, SameSite=Strict, with configurable `device_ttl_seconds` (default 2,592,000). An OTP challenge is bound to its device token; a device may try at most `device_numbers_per_day` distinct phone numbers per UTC day (default 3), including numbers with no invoice. A cookie identifies a browser installation, not tamper-proof hardware: clearing/replacing it resets that identity. Native JSON clients send a securely generated 32-byte base64url token as `X-Kandoo-Device` on both issue and verify requests, and must store and protect it; changing it likewise creates a new identity.

Issue and verify have separate configurable per-IP per-minute limits (`issue_ip_limit_per_minute`, default 10; `verify_ip_limit_per_minute`, default 20). The peer `REMOTE_ADDR` is used, never untrusted forwarded headers. Behind a reverse proxy, all clients may share the proxy peer bucket; deploying trusted proxy attribution requires a separate security design. Limits and lifetimes must be tuned on the host; phone numbers and peer addresses are not stored in the new device/IP counters in raw form.

The authenticated, default-off admin page offers an OTP budget reset. It checks Basic credentials, an HTTPS same-origin request and a CSRF token; the reset is serialized with issuance and writes an audit event without recording a phone in the event. It resets the consumed code counter for that number's announcements. OTP request requires an invoice and an actual delivered announcement; no-invoice requests get a generic invalid response. Existing `max_attempts` is configurable and should be set to 3, and `codes_per_announcement` cannot exceed 2. API tokens and session cookies must not be logged; real SMS remains separately gated.
