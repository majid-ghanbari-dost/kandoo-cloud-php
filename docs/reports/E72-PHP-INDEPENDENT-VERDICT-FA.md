# رأی مستقل PHP — E-72 Canonical Invoice v1.2

**رأی: مغایر / عدم تأیید سازگاری اجرایی فعلی.** این رأی پیشنهاد Python را رد حقوقی یا محصولی نمی‌کند؛ به معنی عدم امکان مصرف بدون قرارداد و نگاشت توافق‌شده است. این گزارش در `kandoo-cloud-php` و شاخه همین نشست ثبت شده است، نه در مخزن جداگانهٔ `kandoo-store-app`.

منبع مستقیم: [`arena/d0587e71-kandoo-digital-invoice`، commit `1e620cc1f990bec51566b5e1af26dcec97f26fdb`](https://github.com/majid-ghanbari-dost/Kandoo-Digital-Invoice/blob/1e620cc1f990bec51566b5e1af26dcec97f26fdb/tests/golden/e72/canonical-invoice-v1-2-draft-vector.json)، ۱۵۰۵ بایت، SHA-256 `0885c7571fb3ccc781f1a73e5505cd94805b065fb13e93f35fa4feb12d061d36`. تگ منبع Python `o16-E-72` به commit `f99ab20f0d39b5e4a293d1c3bce9413d9b77d791` اشاره می‌کند و همان بایت‌های بردار را دارد. مرجع C# `src/Kandoo.Core/CanonicalInvoiceConsumer.cs` در main `cb1730aa7e41768e3b431c7b4ead8968e3d92c9d`، blob `5f06ec05318c2932c5114d0078b335df29b50b0b`؛ [گزارش C# commit 26d8806](https://github.com/majid-ghanbari-dost/Kandoo/blob/26d88067b6d8bc2d66458443d7817cfc6e6d222e/docs/reports/E72-CANONICAL-INVOICE-V1-2-CSHARP-COMPARISON-FA.md) نیز خوانده شد. بردار مستقیماً در دسترس بود و نتیجه صرفاً مبتنی بر گزارش C# نیست.

- **ساختار و عمر:** wrapper بردار خود Canonical Invoice v0 نیست؛ در `base_invoice`، `line_items[0].quantity` و `provenance.fields.line_items[0].quantity` با مصرف‌کننده C# که `quantity_millis` می‌خواهد مغایرند. به‌ترتیب اعتبارسنجی، ردیف کالا با فیلد ناشناخته `quantity` ابتدا رد می‌شود؛ بعد از رفع آن، provenance نیز نیازمند اصلاح است. `state=DRAFT` با `display_number="SYN-E72-001"` و provenance برابر `native` ناسازگار است؛ C# برای پیش از صدور `null` و `unavailable` می‌خواهد. این موارد **بازبینی ایستا** هستند؛ C# در این محیط اجرا نشده است.
- **تصحیح گزارش C#:** ادعای دو فیلد `image_sha256` و `template_library_id` در ریشهٔ `base_invoice` با خود بردار منطبق نیست: هر دو داخل `provenance` هستند و C# در همان سطح آن‌ها را مجاز می‌داند. همچنین برای display پیش از صدور کد اختصاصی `DISPLAY_NUMBER_BEFORE_ISSUE` تعریف شده، نه لزوماً `SCHEMA_VALIDATION_FAILED`. خطاهای متوالی تنها پس از رفع خطای قبلی قابل مشاهده‌اند؛ ادعای سه خطای هم‌زمان نداریم.
- **PHP store/API:** آزمون مستقل PHP بر پایه fixture معتبر Cloud، `cheque` بردار را در v1.1 با 400 `VALIDATION_ERROR` و rollback رد کرد؛ با جایگزینی cheque با cash برای جداسازی آزمایش، تخفیف و walk-in در projection و JSON عمومی ظاهر نشدند. API مشتری نیز طبق بررسی کد فقط whitelist فعلی را ارائه می‌دهد. آزمون این سناریو MemoryGateway است نه اثبات انتهابه‌انتهای C#/MariaDB. commit آزمون [`9d7d1d18c77af32ff814edede7dd076a29232745`](https://github.com/majid-ghanbari-dost/kandoo-cloud-php/commit/9d7d1d18c77af32ff814edede7dd076a29232745)، [CI سبز](https://github.com/majid-ghanbari-dost/kandoo-cloud-php/actions/runs/45366035330). Marker و UUIDهای دو مدل نیز یکسان نیستند.
- **بایت:** Parser/Writer PHP همان تک بردار را با hash فوق بازتولید کرد ([CI](https://github.com/majid-ghanbari-dost/kandoo-cloud-php/actions/runs/45353403490))؛ این تأیید فرمت همان فایل است، نه پذیرش معنایی یا همه ورودی‌ها. Python و U7 برای کنترل‌ها و DEL escape متفاوت دارند. توافق بر پروفایل و وکتورهای مشترک، سپس تصمیم PM درباره addendum لازم است؛ frozen و runtime تغییر نکردند.
