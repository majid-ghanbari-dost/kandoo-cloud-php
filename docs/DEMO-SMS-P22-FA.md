# پیام دمو — P-22

فقط پروفایل `demo` روی LAN خصوصی: هیچ تماس شبکه‌ای با Faraz انجام نمی‌شود. متن اعلان و کد در صندوق پیام admin روی رایانه مالک و در `.kandoo-demo/sms.log` محلی ذخیره می‌شوند؛ هر دو حاوی شماره و کد هستند و به حفاظت و پاک‌سازی مناسب نیاز دارند. از دادهٔ واقعی استفاده نکنید. لاگ در پوشهٔ محدودشدهٔ کاربر است، به git نمی‌رود و هرگز برای پشتیبانی بیرونی ارسال نشود. پیام‌ها واقعی نیستند؛ ذخیره‌شدن به معنای تحویل پیامک نیست.

برای شبیه‌سازی اعلان فاکتور موجود پس از replication، در PowerShell جدید در پوشهٔ مخزن ابتدا `$env:KANDOO_CONFIG = "$PWD\.kandoo-demo\config.php"` را بگذارید. شناسه فروشگاه و فاکتور را از Hub بگیرید، `$id = (New-Guid).Guid` بسازید و `C:\xampp\php\php.exe bin\announcement.php send $id <store-id> <invoice-id>` را اجرا کنید. پیام در outbox ثبت می‌شود. پس از مشاهدهٔ محلی، `C:\xampp\php\php.exe bin\announcement.php confirm $id` را اجرا کنید تا فقط برای این دمو اعلان تأیید و سهمیه دو کد باز شود. این تأیید صرفاً شبیه‌سازی است. سپس مشتری وارد `/account/login` می‌شود؛ کد را مالک از صفحهٔ admin محلی می‌بیند. هیچ تأیید خودکار delivery برای Faraz انجام نمی‌شود.

P-20های نصب‌شده قبل از P-21 که `customer_auth.enabled` در config آن‌ها false است، تنظیماتشان به‌صورت خودکار بازنویسی نمی‌شود؛ پیش از تغییر دستی پشتیبان بگیرید و بر اساس مقادیر نصب جدید در `bin/demo-setup.php` و pepper تصادفی مستقل، تنظیم کنید. اتمام و آزمایش تجربهٔ یک‌اسکریپتی برای این حالت در P-23 بررسی خواهد شد.
