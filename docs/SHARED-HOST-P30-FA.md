# طرح مرحله‌ای استقرار هاست مشترک E1 — P-30

وضعیت: **ناتمام، برای استقرار واقعی تأیید نشده است**. راهنمای پایهٔ `docs/DEPLOY-GUIDE-FA.md` را بدون تغییر قرارداد بخوانید. هدف PHP 8.1 و MariaDB 10.6 با utf8mb4 است؛ قابلیت‌ها و محدودیت‌های هاست واقعی هنوز بررسی نشده‌اند.

1. پیش از استفاده، مالک HTTPS و ریشهٔ وب را فقط روی `public/` تنظیم کند؛ تنظیمات، کلیدها، log، backup و ابزارهای CLI باید خارج از web root و با مجوز محدود بمانند. کلید یا دادهٔ واقعی در مخزن/گزارش قرار نگیرد.
2. نسخهٔ PHP و افزونه‌های لازم، نسخهٔ MariaDB، مسیر cron، پشتیبانی TLS خروجی و سیاست هاست برای `api.iranpayamak.com` بررسی شود. outbound IP فقط برای تطبیق عملیاتی ثبت شود، نه در اختیار سرویس نامعلوم گذاشته شود؛ سازوکار امن و endpoint هنوز مشخص/پیاده‌سازی نشده است.
3. DB مجزا با utf8mb4 ساخته و migration طبق راهنمای پایه اجرا شود. بعد از پشتیبان‌گیری، self-test با دادهٔ ساختگی و بدون SMS واقعی انجام شود. در حال حاضر `bin/selftest.php --sample` فقط DB آزمایشی `TEST_` را قبول می‌کند و self-test محافظت‌شده با secret مورد P-30 **هنوز وجود ندارد**.
4. cron و heartbeat امن، backup شبانه در محل جدا از DB و web root، سیاست مجوز و retention پشتیبان، و بازیابی روی DB مجزای خالی باید پیاده‌سازی و آزموده شوند. هیچ دستور destructive بازیابی روی DB موجود را بدون فرآیند تأیید و جلوگیری از overwrite اجرا نکنید. **آزمون restore هنوز انجام نشده است.**
5. قبل از هر انتشار، تنظیم proxy، نگهداری لاگ URI/token و محدودسازی admin طبق `docs/SECURITY-REVIEW-P34.md` باید جداگانه بررسی شوند؛ سبز بودن CI معادل تأیید deploy نیست.

### پیشرفت heartbeat (مرحله‌ای)

Migration `0010_cron_heartbeat.sql` فقط زمان آخرین تکمیل موفق نگهداری را در DB ذخیره می‌کند؛ `bin/cron.php` تنها بعد از موفقیت prune و cleanup آن را ثبت می‌کند. زمان آینده و نبود سابقه سالم تلقی نمی‌شوند و اجرای قدیمی نمی‌تواند زمان را عقب ببرد. مجوز DB و نتیجه باید خصوصی بمانند؛ این به‌تنهایی ابزار پایش/هشدار عملیاتی یا خودآزمایی محافظت‌شده نیست. پیش از فعال‌سازی روی هاست واقعی نسخه پشتیبان معتبر بگیرید، migration را طبق راهنمای پایه اجرا و cron را از حساب محدود میزبان تنظیم کنید. خودآزمایی، اعلام هشدار، انتقال پشتیبان جداگانه و بازیابی هنوز تکمیل نشده‌اند.

### عیب‌یابی محافظت‌شده (CLI؛ هنوز تأیید استقرار نیست)

`bin/host-diagnostics.php` فقط CLI است و بدون کلید مستقل ۳۲ بایتی، به‌شکل ۶۴ رقم hex کوچک، از stdin اجرا نمی‌شود. هش SHA-256 همان رشتهٔ hex در متغیر محیطی `KANDOO_HOST_DIAGNOSTICS_KEY_SHA256` تنظیم شود؛ مقدار واقعی فقط در فایل خصوصی خارج از web root و با مجوز 0600 ذخیره شود و از فایل به stdin هدایت گردد، نه در آرگومان، URL، تاریخچهٔ shell یا لاگ. هش و کلید نباید با رمز یا کلیدهای دیگر مشترک باشند. محیط و حساب CLI را محدود کنید؛ این ابزار endpoint وب ندارد. کلید را پس از افشا فوراً تعویض کنید. خروجی JSON شامل IP و اطلاعات نسخه است؛ فقط برای اپراتور مجاز و بدون ثبت عمومی استفاده شود.

آزمایش PHP، افزونه‌ها، نسخه MariaDB، round-trip فقط خواندنی utf8mb4 با متن ساختگی، تازگی heartbeat و اتصال TLS به `api.iranpayamak.com:443` را انجام می‌دهد؛ اتصال TLS نشان‌دهندهٔ تأیید الگو یا تحویل پیامک نیست. IP عمومی با GET ثابت HTTPS به `api.ipify.org` مشخص می‌شود؛ آن سرویس IP عمومی میزبان را می‌بیند، هیچ کلید، شماره یا دادهٔ مشتری به آن فرستاده نمی‌شود. اگر این انتقال یا شبکه میزبان مجاز نیست، ابزار شکست را گزارش می‌کند و IP باید جداگانه با روش مورد تأیید اپراتور بررسی شود. این تست مسیر IP به سرویس echo را نشان می‌دهد و وجود NAT یا مسیر متفاوت تا فراز ممکن است IP دیگری بسازد؛ با provider/هاست تطبیق دهید. سرویس echo در CI فراخوانی نمی‌شود و نتیجهٔ واقعی هاست هنوز NOT-VERIFIED است. بازگرداندن backup همچنان باید روی DB مجزای خالی آزموده شود.
